# Архитектура HarnessHub

Harness — родной AI-клиент. Provider ID — постоянный идентификатор адаптера.
Профиль — отдельный каталог конфигурации конкретного harness и метаданные менеджера.
Подписка и аккаунт определяются родным клиентом после входа.

## Слои

| Модуль | Ответственность |
| --- | --- |
| `registry.py` | Возможности harness, команды, переменные конфигурации и ссылки на документацию |
| `models_catalog.toml` / `catalog_loader.py` | Декларативный реестр алиасов моделей, отображаемых названий, дефолтных наборов и замен с пользовательским оверрайдом |
| `store.py` | Схема реестра v2, миграция v1, валидация, атомарное сохранение метаданных |
| `locking.py` | Межпроцессные блокировки (`LOCK_SH` для параллельных сессий, `LOCK_EX` для мутирующих операций) и инспекция активности |
| `proc.py` / `rpc.py` | Кроссплатформенная изоляция процессов/деревьев и потоковый JSON-RPC stdio-клиент без `select()` на пайпах |
| `service.py` | Жизненный цикл профилей, импорт, дочернее окружение, запуск и оркестрация |
| `providers/{base,agy,codex,claude}.py` | Изолированные адаптеры провайдеров: телеметрия, живые пробы квот и парсинг транскриптов |
| `telemetry.py` | Публичный фасад телеметрии аккаунтов поверх `providers/*` |
| `usage.py` | Сводка окон квот (Codex RPC, AGY ACP/Cloud Code, Claude `auth status` + локальные кулдауны без подмены неизвестных значений) |
| `models.py` | Реестр моделей, нормализация алиасов, тиры AGY, кулдауны и ранжирование слотов с учётом подтверждённой квоты и мягкой балансировки активности |
| `sessions.py` | Единый индекс историй чата (Codex `state_5.sqlite` + JSONL, AGY `conversation_metadata.json` + транскрипты, Claude JSONL), поиск, resume и handoff |
| `ide.py` | Изолированный запуск Electron IDE (Antigravity IDE, VS Code, Cursor) с `--user-data-dir`, разделением env по провайдерам и защитой секретов прокси |
| `consult.py` | Headless read-only вызов второго мнения / консилиума (`--mode plan` / `--permission-mode plan` / `-s read-only`) с автосбором контекста и `git diff` |
| `mcp.py` | Встроенный многопоточный JSON-RPC 2.0 MCP-сервер (`stdio`) с валидацией аргументов и изоляцией stdout |
| `agy.py` | Отдельная транзакция патчинга, атомарный бэкап, быстрая проверка манифеста и откат |
| `agy_workspace.py` | Определение канонического HOME, общая история чатов AGY (слияние + симлинки без смешивания токенов) и синхронизация `settings.json`/скиллов |
| `network.py` | Политики прокси, наследование, дочернее окружение, скрытие userinfo |
| `installation.py` | Официальные источники, поколения установок, проверка и активация |
| `cli.py` / `tui/*` | CLI и модульный TUI (`tui/{app,modals,formatters,runner}.py`) поверх общих сервисов |

UI не реализует OAuth и не принимает токены. Текстовый интерфейс завершает текущий цикл
перед запуском интерактивного дочернего процесса; синхронный supervisor ждёт завершения,
сохраняя разделяемую блокировку профиля, и возвращает пользователя в TUI.

## Состояние v2

`state.json` содержит `version`, `profiles`, `defaults`, `custom`, `settings`,
`network`, `installations`. Версия v1 сначала проходит собственную валидацию, затем
мигрирует в памяти; файл записывается в v2 только при следующем явном изменении.
У профиля есть `provider`, `name`, абсолютный `path`, признак внешнего владения `external`,
`autoheal` и время регистрации. Имя изменяется независимо от пути. Пути уникальны
после канонизации. В реестре нет OAuth-токенов и API-ключей. В отличие от остальных клиентов,
проба живых квот AGY читает локальный файл `antigravity-oauth-token` из каталога профиля AGY
(после обновления токена через `agy acp`) для запроса Cloud Code квот, не сохраняя его в `state.json`.
Опциональная авторизация прокси хранится внутри его URL в защищённом локальном файле и скрыта
во всех публичных представлениях профилей, команд IDE и настроек.

Все изменения реестра проходят под отдельной эксклюзивной блокировкой и заменяют файл целиком.
Неизвестная версия схемы останавливает работу вместо сброса данных.

Ресурсные блокировки живут в общем пользовательском state-каталоге и используют hash
канонического пути. Они одинаковы для разных `--data-dir`. Обычные диалоги (`run`, `smart`,
`resume`, `handoff`), `consult` и `ide` используют **разделяемые блокировки (`LOCK_SH`)**, позволяя
одновременно вести несколько параллельных диалогов на одном аккаунте. **Эксклюзивная блокировка
(`LOCK_EX`)** применяется только при `login`, `remove`, патчинге бинарника AGY и обновлении `state.json`.
На POSIX используется `flock`, на Windows — `LockFileEx` (`LOCKFILE_FAIL_IMMEDIATELY`); lock-файлы не удаляются и не передаются дочернему процессу.

Политики прокси используют режимы `inherit`, `direct`, `url` и необязательные исключения.
Профиль наследует глобальную политику, глобальная — окружение. Установщик применяет
прокси профиля только при явном выборе. Окружение самого менеджера не изменяется. При запуске
IDE прокси с авторизацией передаётся через окружение процесса, а не в аргумент `--proxy-server`.

Установка выполняется под отдельной блокировкой harness в новом каталоге поколения.
Метаданные публикуются после проверки ожидаемого entrypoint, а старые поколения
сохраняются. При ошибке очистка проверяет под блокировкой реестра, что каталог не опубликован.
Для Junie сохраняется отдельный `JUNIE_DATA` внутри поколения; аккаунт использует реальный HOME.
Установка AGY сбрасывает предыдущий `agy_binary` в той же транзакции активации.

## Расширение

1. Launch-only адаптер: исполняемая команда и документация о подписочном входе.
2. Профили: подтверждённый механизм конфигурации и credential store на каждой ОС.
3. Квоты: собственный reader с источником, временем проверки, окнами и сроками сброса.
4. Обслуживание: отдельные явные операции с проверяемым результатом и откатом.

Наличие записи в каталоге не означает поддержку всех уровней. Отсутствующие данные квот
представляются пустым списком окон или `None`, а не нулём или ста процентами остатка.
Пользовательские адаптеры регистрируют команды декларативно и не загружают Python-плагины.
Каталог моделей можно расширять пользовательским `models_catalog.toml` в `--data-dir`.

## Следующие самостоятельные расширения

- AGY: квоты, модели, ARM64 и PE/Mach-O; отдельные тестовые бинарники и подпись macOS.
- Claude, Kimi, Qoder: живые квоты и проверка аккаунта штатными механизмами клиентов.
- Copilot, Cursor, Gemini, Kiro, Junie: проверенная изоляция профилей вместо launch-only.
- Очереди задач и правила выбора профиля с учётом стоимости моделей.
- История запусков, синхронизация общих инструкций и skills.
- SOCKS, проверка доступности прокси и системные credential stores для его паролей.
- Проверенные пути выполнения vendor-установщиков Windows после загрузки.
- Релизные standalone-сборки и проверки двух аккаунтов на каждой поддерживаемой ОС.

Существующие `agyprof`, `codexprof`, `agyq` и `codexq` сохраняют свои команды и данные.
HarnessHub подключает их каталоги через явную регистрацию и запускает сами harness.
